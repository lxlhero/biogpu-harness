## 1. 核心目标

`check_completion_gate.py` 用于判断某个 workflow 阶段是否真的完成。

它不是普通 validator。

validator 回答：

```text
配置文件是否合法？
状态文件是否合法？
```

completion gate 回答：

```text
这个阶段是否真的完成？
是否有足够 artifact / report / event evidence？
是否可以进入下一步？
失败时应该交给哪个 agent 诊断？
```

## 4. 通用前置检查

所有 gate 都必须先检查：

```text
1. biogpu_project.yaml 存在
2. state/task_state.json 存在
3. state/trace_context.json 存在
4. logs/events.jsonl 存在
5. validate_biogpu_project.py pass
6. validate_task_state.py pass
```

如果这些不通过，gate 直接 fail。

失败时输出建议：

```text
recommended_next_agent = bio-gpu-trace-analyst-agent
```

---

## 5. project_init gate

`project_init` 必须检查：

```text
1. biogpu_project.yaml validate pass
2. task_state.json validate pass
3. trace_context.json 存在并包含 trace_id / session_id / root_span_id
4. workspace_path 不在 HARNESS_ROOT 下
5. reports / runs / baseline / logs / artifacts 路径合法
```

通过后：

```text
status = pass
next_action = run_benchmark 或 plan_existing_project
```

---

## 6. test_plan gate

`test_plan` 检查：

```text
1. reports/test_plans/<test_suite>_test_plan.md 存在
2. test_plan 中包含 precision_config
3. precision_config.metrics 非空
4. 每个 metric 至少有 name
5. 需要 cpu_file/gpu_file 的 metric 必须字段完整
6. threshold / direction 必须存在，除 exact_match / row_count_match / file_exists 可例外
```

如果没有 `precision_config`，必须 fail。

推荐：

```text
recommended_next_agent = bio-gpu-test-planner-agent
```

---

## 7. primary_e2e gate

`primary_e2e` 检查：

```text
1. reports/test_plans/<test_suite>_test_plan.md 存在
2. reports/test_results/<test_suite>_precision.json 存在
3. reports/test_results/<test_suite>_precision.md 存在
4. precision.json status = pass
5. logs/events.jsonl 中存在 test_completed pass 或 command_executed pass 事件
6. 对应事件必须包含 trace_id / session_id / span_id
7. 如果事件里有 artifact_path，该 artifact 必须存在
```

如果 precision.json 缺失：

```text
recommended_next_agent = bio-gpu-test-runner-agent
```

如果 event/artifact 证据链不一致：

```text
recommended_next_agent = bio-gpu-trace-analyst-agent
```

---

## 8. double_check_e2e gate

先读取：

```text
biogpu_project.yaml benchmarks.double_check_e2e.status
```

如果是：

```text
not_requested
```

则 gate 返回：

```text
status = skipped
```

exit code 仍为 0。

如果 double_check 被 requested / planned / approved / running / pass / fail，则必须检查：

```text
1. double_check test_plan 存在
2. double_check precision.json 存在
3. precision.json status = pass
4. events.jsonl 有 double_check_e2e completed/pass 证据
```

---

## 9. final_delivery gate

`final_delivery` 检查：

```text
1. primary_e2e gate pass
2. 如果 double_check_e2e not_requested，则允许跳过
3. 如果 double_check_e2e requested，则 double_check_e2e gate 必须 pass
4. reports/final_report.md 或 reports/final_optimization_summary.md 存在
5. final report 中必须引用 precision evidence
6. final report 中必须引用 runtime/speed evidence
7. events.jsonl 中有 final_report_written pass 事件
```

如果缺 final report：

```text
recommended_next_agent = bio-gpu-doc-writer-agent
```

如果证据链不完整：

```text
recommended_next_agent = bio-gpu-trace-analyst-agent
```

  "status": "pass",

{
