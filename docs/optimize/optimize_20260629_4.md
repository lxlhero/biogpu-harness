# Phase 2.4-A：Hooks / Hard Gate 最小闭环

进入 Phase 2.4-A。

目标：把 BioGPU-Harness 目前已有的 validator、schema、tracing、completion gate 接入 Claude Code hooks，形成最小 hard gate。

本阶段只做最小 hooks，不做 CI，不做 dashboard，不做 rjob_submit.py，不做真实工具工作区修改。

```bash
/Users/huron/miniconda3/envs/biogpu-harness/bin/python
```

## 1. 本阶段目标

当前系统已经有：

```text
validate_biogpu_project.py
validate_task_state.py
init_trace_context.py
log_event.py
compare_precision.py
check_completion_gate.py

```

但目前多数检查还是 soft rule，依赖 agents 自觉执行。

Phase 2.4-A 要实现最小 hard gate：

```text
1. 修改 biogpu_project.yaml 后自动校验 project
2. 修改 state/task_state.json 后自动校验 task_state
3. 修改 state/trace_context.json 后自动校验 trace_context schema
4. 修改 logs/events.jsonl 后自动校验最后一条 event schema
5. 生成 test_plan 后自动检查 precision_config
```

## 2. 新增 hook 脚本

新增：

```text
scripts/hook_validate_file.py
```

作用：根据被修改文件路径，自动选择对应校验逻辑。

支持调用：

```bash
/Users/huron/miniconda3/envs/biogpu-harness/bin/python scripts/hook_validate_file.py \
  --file <modified_file_path>
```

必须支持以下文件类型：

```text
biogpu_project.yaml
state/task_state.json
state/trace_context.json
logs/events.jsonl
reports/test_plans/*_test_plan.md
```

---

## 3. hook_validate_file.py 规则

### 3.1 biogpu_project.yaml

如果修改的是：

```text
<workspace>/biogpu_project.yaml
```

运行：

```bash
python scripts/validate_biogpu_project.py --workspace <workspace>
```

fail 则 hook fail。

---

### 3.2 task_state.json

如果修改的是：

```text
<workspace>/state/task_state.json
```

运行：

```bash
python scripts/validate_task_state.py --workspace <workspace>
```

fail 则 hook fail。

---

### 3.3 trace_context.json

如果修改的是：

```text
<workspace>/state/trace_context.json
```

运行：

```bash
python scripts/validate_schema.py \
  --schema schemas/trace_context.schema.json \
  --file <workspace>/state/trace_context.json
```

fail 则 hook fail。

---

### 3.4 events.jsonl

如果修改的是：

```text
<workspace>/logs/events.jsonl
```

只校验最后一行 event。

可以在 `hook_validate_file.py` 内部读取最后一行并用：

```text
schemas/event.schema.json
```

校验。

fail 则 hook fail。

---

### 3.5 test_plan

如果修改的是：

```text
<workspace>/reports/test_plans/*_test_plan.md
```

必须检查：

```text
1. markdown 中存在 precision_config YAML block
2. precision_config 能通过 schemas/precision_config.schema.json
```

fail 则 hook fail。

注意：这里不执行 compare_precision.py，只检查 test_plan 结构和 precision_config。

## 4. 输出格式

hook_validate_file.py 输出 JSON。

pass：

```json
{
  "status": "pass",
  "file": "<path>",
  "checks": ["validate_task_state"],
  "errors": [],
  "warnings": []
}
```

fail：

```json
{
  "status": "fail",
  "file": "<path>",
  "checks": ["precision_config_schema"],
  "errors": [
    {
      "type": "missing_precision_config",
      "message": "test_plan does not contain precision_config"
    }
  ],
  "warnings": []
}
```

退出码：

```text
pass: 0
hook fail: 1
script error: 2
```

## 5. 配置 Claude Code hook

如果当前项目使用 `.claude/settings.json`，则新增或更新：

```text
.claude/settings.json
```

加入 PostToolUse hook。

建议先只对 Write / Edit / MultiEdit 后触发：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "/Users/huron/miniconda3/envs/biogpu-harness/bin/python /Users/huron/code/ai_lab/biogpu-harness/scripts/hook_validate_file.py --file \"$CLAUDE_FILE_PATH\""
          }
        ]
      }
    ]
  }
}
```

如果 Claude Code 的实际 hook 环境变量不是 `CLAUDE_FILE_PATH`，请根据当前 Claude Code hook 文档或现有项目实践调整，但必须在文档中写明实际变量。

如果无法稳定获取 modified file path，则先实现脚本和文档，不强行启用 hook。
