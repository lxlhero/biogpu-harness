## 1. 核心定位

`compare_precision.py` 是通用 precision metric executor。

它不负责理解具体生信工具。

它不负责决定：

```text
1. 这个工具应该用什么精度指标
2. threshold 应该是多少
3. 输出文件应该怎么从原始格式解析
```

这些由 agent 负责：

```text
bio-gpu-test-planner-agent
  → 决定 precision_metrics / threshold / direction

bio-gpu-test-runner-agent
  → 运行 CPU/GPU，并把复杂输出整理成 normalized TSV/CSV

compare_precision.py
  → 根据 test_plan 中的 precision_config 执行指标计算

bio-gpu-problem-analyst-agent
  → 精度失败后分析原因
```

所以 Phase 2.1-C 只实现：

```text
通用指标计算 + pass/fail 判断 + JSON/Markdown 报告输出
```

不实现工具专属逻辑。

## 3. test_plan 中的 precision_config 格式

`bio-gpu-test-planner-agent` 后续必须在 test plan 中写入 YAML code block：

````markdown
```yaml
precision_config:
  test_suite: primary_e2e
  metrics:
    - name: pearson
      cpu_file: baseline/primary_e2e/normalized_cpu_scores.tsv
      gpu_file: runs/primary_e2e/normalized_gpu_scores.tsv
      key_column: gene_id
      value_column: score
      threshold: 0.99
      direction: ">="
    - name: jaccard
      cpu_file: baseline/primary_e2e/normalized_cpu_gene_set.tsv
      gpu_file: runs/primary_e2e/normalized_gpu_gene_set.tsv
      key_column: gene_id
      threshold: 0.95
      direction: ">="
```
````

脚本需要从 markdown 中提取第一个包含：

```text
precision_config:
```

的 YAML code block。

如果没有找到，返回 error，exit 2。


## 5. 输入文件假设

本阶段只支持标准化后的文件：

```text
TSV / CSV
```

复杂工具原始输出不由 `compare_precision.py` 直接解析。

如果工具输出是：

```text
RDS
MTX
复杂目录
多文件 report
非标准文本
```

必须先由 `bio-gpu-test-runner-agent` 转换为 normalized TSV/CSV，再交给 `compare_precision.py`。

## 6. metric 规则

### pearson / spearman

需要：

```text
cpu_file
gpu_file
value_column
threshold
direction
```

可选：

```text
key_column
```

如果有 `key_column`，按 key 对齐；否则按行顺序对齐。

---

### rmse / mae / max_abs_error / relative_error

需要：

```text
cpu_file
gpu_file
value_column
threshold
direction
```

通常：

```text
direction: "<="
```

支持 `key_column` 对齐。

---

### jaccard

需要：

```text
cpu_file
gpu_file
key_column
threshold
direction
```

计算：

```text
|CPU ∩ GPU| / |CPU ∪ GPU|
```

---

### f1

需要：

```text
cpu_file
gpu_file
label_column
threshold
direction
```

可选：

```text
key_column
```

如果有 key，按 key 对齐；否则按行顺序对齐。

---

### exact_match

需要：

```text
cpu_file
gpu_file
```

比较文件内容是否完全一致。

---

### row_count_match

需要：

```text
cpu_file
gpu_file
```

比较行数是否一致。

---

### file_exists

需要：

```text
file
```

或：

```text
gpu_file
```

检查文件是否存在。

---

### ratio

适合 sigma²、h² 等标量或单列数值。

需要：

```text
cpu_file
gpu_file
value_column
threshold_low
threshold_high
```

示例：

```yaml
- name: ratio
  cpu_file: baseline/primary_e2e/normalized_cpu_params.tsv
  gpu_file: runs/primary_e2e/normalized_gpu_params.tsv
  key_column: param
  value_column: value
  threshold_low: 0.99
  threshold_high: 1.01
```

计算：

```text
gpu_value / cpu_value
```

要求 ratio 在 `[threshold_low, threshold_high]` 内。

## 7. 输出 JSON

成功示例：

```json
{
  "status": "pass",
  "test_suite": "phase2_1",
  "metrics": [
    {
      "name": "pearson",
      "value": 0.99998,
      "threshold": 0.99,
      "direction": ">=",
      "status": "pass",
      "cpu_file": "baseline/phase2_1/cpu_scores.tsv",
      "gpu_file": "runs/phase2_1/gpu_scores.tsv"
    }
  ],
  "failed_metrics": [],
  "errors": []
}
```

失败示例：

```json
{
  "status": "fail",
  "test_suite": "phase2_1",
  "metrics": [
    {
      "name": "pearson",
      "value": 0.98,
      "threshold": 0.99,
      "direction": ">=",
      "status": "fail"
    }
  ],
  "failed_metrics": ["pearson"],
  "errors": []
}
```

脚本错误示例：

```json
{
  "status": "error",
  "reason": "missing_precision_config",
  "metrics": [],
  "failed_metrics": [],
  "errors": [
    "test_plan does not contain precision_config"
  ]
}
```
