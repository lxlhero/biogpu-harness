# Phase 2.3-A：Schema 正式化第一步

进入 Phase 2.3-A。

目标：把 BioGPU-Harness 目前已经稳定下来的核心数据结构沉淀成 schema，为后续 hooks、CI、hard gate 做准备。

本阶段只做 schema 文件和基础校验，不做 hooks，不做 CI，不做 rjob_submit.py。

---

## 1. 新增 schemas 目录

新增：

```text
schemas/
```

并创建 5 个 schema 文件：

```text
schemas/biogpu_project.schema.json
schemas/task_state.schema.json
schemas/trace_context.schema.json
schemas/event.schema.json
schemas/precision_config.schema.json
```

---

## 2. schema 覆盖范围

### biogpu_project.schema.json

覆盖：

```text
tool_name
mode
harness
paths
source
user_request
benchmarks
precision
```

必须限制：

```text
mode: A / B
harness.entrypoint: /bio-gpu-team
source.status: pending / ready / failed / user_provided
precision.policy: auto / planned / approved / fixed
```

路径是否在 workspace 下，可以继续留给 `validate_biogpu_project.py` 做自定义逻辑，不一定写进 JSON schema。

---

### task_state.schema.json

覆盖：

```text
task_id
tool_name
mode
current_step
current_role
current_module
module_queue
attempt
max_attempts_per_module
next_action
last_result
human_approval_required
approval_reason
approved
tests
session_request
```

必须限制：

```text
mode: A / B
next_action: 使用当前 validate_task_state.py 的白名单
session_request.request_type: 使用当前 request_type 白名单
```

规则：

```text
A 模式 session_request 可以为 null
B 模式 session_request 非空这个逻辑可以继续留给 validate_task_state.py 做自定义检查
```

---

### trace_context.schema.json

覆盖：

```text
task_id
tool_name
session_id
trace_id
root_span_id
current_span_id
created_at
created_by
updated_at
notes
```

要求：

```text
session_id / trace_id / root_span_id / current_span_id 可以是 string 或 null
```

模板里可以是 null，实际运行后应由 `init_trace_context.py` 补齐。

---

### event.schema.json

覆盖 events.jsonl 每一行：

```text
event_id
timestamp
tool_name
task_id
session_id
trace_id
span_id
parent_span_id
agent
event_type
status
step
module
attempt
decision_id
command_id
artifact_id
artifact_path
command
exit_code
next_action
message
```

限制：

```text
status: pass / fail / running / blocked / warning / info
event_type: 使用 log_event.py 当前白名单
```

---

### precision_config.schema.json

覆盖 test_plan 中的：

```yaml
precision_config:
  test_suite:
  metrics:
```

每个 metric 至少包含：

```text
name
```

支持 metric：

```text
pearson
spearman
rmse
mae
max_abs_error
relative_error
jaccard
f1
exact_match
row_count_match
file_exists
ratio
```

不同 metric 的复杂字段校验可以先留给 `compare_precision.py` 做自定义检查。

```text

schema validation fail exit 1

```
