## 1. validate_biogpu_project.py 接入 schema

文件：

```text
scripts/validate_biogpu_project.py
```

新增逻辑：

```text
1. 读取 biogpu_project.yaml
2. 先用 schemas/biogpu_project.schema.json 做 schema 校验
3. schema fail 时直接 fail，exit 1
4. schema pass 后继续执行原有自定义检查
```

自定义检查继续保留：

```text
workspace_path 不能是 HARNESS_ROOT
workspace_path 不能在 HARNESS_ROOT 下
reports/runs/baseline/logs/benchmarks/artifacts 必须在 workspace_path 下
state_path 必须在 workspace_path/state/ 下
bio_tool_path 必须在 workspace_path 下
```

输出 JSON 里要区分：

```json
{
  "status": "fail",
  "schema_errors": [],
  "custom_errors": [],
  "warnings": []
}
```

## 2. validate_task_state.py 接入 schema

文件：

```text
scripts/validate_task_state.py
```

新增逻辑：

```text
1. 读取 state/task_state.json
2. 先用 schemas/task_state.schema.json 做 schema 校验
3. schema fail 时直接 fail，exit 1
4. schema pass 后继续执行原有 workflow 自定义检查
```

自定义检查继续保留：

```text
A 模式 session_request 可以为 null
B 模式 session_request 不能为 null
B 模式 session_request.request_type 必须合法
B 模式 session_request.mode 必须是 B
next_action 必须在白名单中
```

输出 JSON 里同样区分：

```json
{
  "status": "fail",
  "schema_errors": [],
  "custom_errors": [],
  "warnings": []
}
```

## 3. 复用 validate_schema.py 逻辑

可以选择两种实现方式：

```text
方案 A：在 validators 内部 import / 复用 validate_schema.py 的函数
方案 B：把 schema 校验逻辑抽成 scripts/lib/schema_utils.py
```

推荐方案 B，但不要过度工程化。

如果新增 helper，路径建议：

```text
scripts/lib/schema_utils.py
```

职责只做：

```text
load_yaml_or_json
load_schema
validate_against_schema
format_schema_errors
```
